# Branching Strategy

## Default Strategy

Use short-lived feature branches merged through pull requests.

## Branch Names

Use:

```text
feature/{domain}-{short-description}
fix/{domain}-{short-description}
docs/{topic}
release/{version}
```

## Pull Requests

Pull requests must include:

- Summary
- Related feature documentation
- Database changes
- API changes
- Frontend changes
- Testing evidence
- Risk and rollback notes
