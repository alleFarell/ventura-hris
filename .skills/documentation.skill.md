# Documentation Skill

## Purpose

Guide documentation-first delivery.

## Guidelines

- Documentation is a project artifact, not a side note.
- Keep docs clear, current, and connected to implementation.

## Do

- Update docs when behavior changes.
- Explain decisions and operational impact.

## Don't

- Leave stale examples or undocumented exceptions.
- Hide business rules only in code.

## Examples

- Update `Feature.md` and `API.md` when adding employee transfer.

## Checklist

- [ ] Purpose clear
- [ ] Rules documented
- [ ] Examples useful
- [ ] Review status visible
